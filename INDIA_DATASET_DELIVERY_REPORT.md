# GeoResQ India Dataset Delivery Report

## Executive result

The GeoResQ prototype was inspected end to end. Its active proof of concept is Mumbai urban-flood decision support, but the dataset request is now implemented as **India-only satellite data**. The complete collected package contains real Indian Sentinel-1 SAR imagery and flood labels from the India event in Sen1Floods11 v1.1. It has been validated locally and published to the SIH GitHub repository.

> The dataset is India-focused, but the downloaded labeled event covers northeastern India rather than every Indian state. The package does not make a false claim of pan-India supervised coverage.

## What the prototype actually needs

The prototype follows a **Hazard → Exposure → Impact → Decision** workflow. Satellite imagery is most appropriate for the Hazard stage: identifying inundated or flood-water pixels. The downstream outputs shown by the prototype—population exposed, hospitals and schools affected, roads affected, shelters required, route risk, and recommended actions—should be generated by GIS overlays and transparent decision rules after the hazard mask is produced. They should not be treated as labels that can be learned from satellite images alone.

The recommended SIH MVP algorithm is therefore a **two-channel U-Net semantic-segmentation model** using Sentinel-1 VV and VH backscatter. Sentinel-1 SAR is appropriate for flood mapping because it can operate through cloud cover, which is common during Indian flood events. The U-Net output is a pixel mask that can be converted into polygons or a raster layer and joined with Indian roads, buildings, population, hospitals, schools, elevation, rainfall, and shelter datasets.

| Prototype capability | Recommended implementation | Satellite dataset role |
|---|---|---|
| Flood hazard map | U-Net segmentation on Sentinel-1 VV/VH | Direct supervised learning target |
| Risk score | Transparent weighted GIS/risk engine | Consume predicted flood mask plus rainfall, elevation, drainage, and historical data |
| Population and infrastructure exposure | PostGIS/GeoPandas spatial intersection | Consume flood mask and Indian exposure layers |
| Safe routes | Road-network routing with flooded/blocked segment penalties | Consume hazard mask and road graph |
| Shelter suitability | Rule-based or learned ranking using capacity, access, flood risk, and hospital distance | Consume facilities and hazard layers |
| Disaster simulator | Hydrological/scenario model with rainfall and drainage inputs | Compare current vs simulated exposure |

## Dataset published

| Item | Verified value |
|---|---:|
| Country | India |
| Source event | Sen1Floods11 v1.1 India event |
| Region | Northeastern India |
| Acquisition date | 2016-08-12 |
| Image sensor | Sentinel-1 GRD SAR |
| Channels | VV and VH |
| Image data type | Float32 dB backscatter |
| Chip size | 512 × 512 pixels |
| Ground resolution | 10 m |
| Training chips | 467, weak Otsu-derived labels |
| Validation chips | 68, hand-labeled masks |
| Total paired chips | 535 |
| Archive size | 876,408,800 bytes |
| Archive SHA-256 | `1540e600f4718a0ab8e31c841e0b73696373afcf07a266d3ee953102d6717152` |

Label values are `-1` for no-data, `0` for not-water, and `1` for water. All 535 image/label pairs are 512 × 512 pixels. The validation script checked file existence, source byte sizes, SHA-256 hashes, image/label pairing, chip shape, and allowed label values. The result was `VALIDATION_OK` with zero errors.

## Usage

From a fresh clone, install the dependencies and download the India-only raw dataset as follows:

```bash
git clone https://github.com/jaidhevprasad-tech/SIH.git
cd SIH
python3 -m pip install -r data/india_flood_segmentation/requirements.txt
python3 scripts/download_india_flood_dataset.py --workers 8
python3 scripts/validate_india_flood_dataset.py
```

Alternatively, download the release archive, extract it from the repository root, and run the same validator. To train the baseline model after PyTorch installation, use:

```bash
python3 data/india_flood_segmentation/scripts/train_unet.py \
  --data-root data/india_flood_segmentation \
  --epochs 20 \
  --batch-size 4 \
  --output-dir runs/india_unet
```

The model is a baseline for the SIH prototype, not an operational emergency system. Its training labels are weakly derived, while its validation labels are hand labeled. Use event-level splits when adding more Indian flood events to avoid spatial leakage.

## India-only expansion recommendation

The present package is a real India-only core, but a production-quality GeoResQ model should add more Indian events and states. The preferred expansion sources are Indian government and ISRO/NRSC services: Bhuvan Disaster Services, Bhuvan open data, Bhoonidhi’s regional Sentinel hub, and verified Indian flood-event products. Each added event should preserve the same schema: India-only Sentinel-1 VV/VH imagery, authoritative or hand-reviewed masks, acquisition timestamp, footprint, source attribution, and license. Recommended future coverage includes Assam/Brahmaputra, Bihar, West Bengal, Odisha, Maharashtra, Kerala, Karnataka, Andhra Pradesh, and Tamil Nadu when suitable labeled events are available.
